# JOBSUIT AI Recreation Roadmap

## Product definition

Build an independent, functional recreation of the observable Jobsuit product experience: an AI resume builder focused on resume creation, analysis, tailoring, refinement and application preparation.

Reference: https://jobsuit.ai/

## Phase 1 — Visual/product reset — IN PROGRESS

Completed:
- Landing page rebuilt around the Jobsuit information architecture.
- Brand metadata changed to JOBSUIT AI prototype.
- Resume Builder rebuilt as the primary workspace.
- Pricing moved to Free / Pro / Elite structure.
- Existing backend/auth infrastructure preserved.

Remaining:
- Full tailoring workspace polish.
- Resume analysis page parity.
- Template gallery.
- Cover-letter workspace.
- Application tracker parity.
- Shared navigation/footer consistency.

## Phase 2 — Resume Builder

- Upload/import PDF, DOCX, TXT and Markdown.
- Editable resume source.
- Target job input.
- Live analysis.
- Resume naming/versioning.
- Browser PDF export.
- Template gallery.
- Template selection.
- Resume preview.
- AI editing affordances.

## Phase 3 — Resume Analysis

- Overall score.
- ATS structure checks.
- Keyword analysis.
- Strengths and gaps.
- Section-level feedback.
- Improvement checklist.
- Accept/reject/edit suggestions.
- Target-job comparison.

## Phase 4 — Resume Tailoring

- Supply job description.
- Compare against current resume.
- Show matched keywords.
- Show missing signals.
- Generate role-specific rewrite suggestions.
- Preserve candidate evidence.
- Review every consequential change.
- Save tailored versions.

## Phase 5 — Resume Agent

- Context-aware chat.
- Section-level editing.
- Explain every suggestion.
- Never invent experience, metrics, employers or credentials.
- Apply / reject / edit suggestion controls.

## Phase 6 — Templates

Build an ATS-friendly template gallery with multiple visual variants and a shared content model.

## Phase 7 — Cover letters

- Generate role-specific draft.
- Resume + job context.
- Editable output.
- Save/export.

## Phase 8 — Application tracker

- Target role.
- Company.
- Resume version.
- Tailored version.
- Application state.
- Notes.
- Lightweight history.

## Phase 9 — Monetisation

Implement authoritative entitlements, checkout, subscription lifecycle and billing only after the core product is stable.

## Phase 10 — Release quality

- Main CI.
- Mobile verification.
- Accessibility.
- Performance.
- Auth/persistence.
- RLS/security.
- PDF export.
- Privacy/deletion.
- Rate limiting.
- Observability.

## Design gate

Preserve the observable strengths of the reference:
- Immediate comprehension.
- Strong CTA hierarchy.
- Product UI visible above the fold.
- Clean card geometry.
- Soft visual contrast.
- Clear before/after storytelling.
- Short paths to first useful output.
- Responsive builder UX.
